# VQA 评测数据批量构建工具

基于 Qwen VL 多模态大模型，从视频文件批量生成 VQA（Video Question Answering）评测数据集。支持自定义类目体系、难度分层、断点续跑和自动校验。

## 项目结构

```
项目根目录/
├── prepare_tasks.py        # 步骤①：读取配置 → 生成任务清单（不调模型）
├── generate_vqa.py         # 步骤②：逐视频调 Qwen VL 生成 VQA（调模型）
├── validate.py             # 步骤③：校验生成结果 → 输出最终数据集（不调模型）
├── prompt_templates.py     # Prompt 模板 + 类目引导语映射表（高级用户扩展用）
├── video_utils.py          # 视频帧提取 + Qwen VL API 调用封装（无需修改）
│
├── category_config.xlsx    # ← 你填写：什么类目 × 各生成多少条
├── video_list.xlsx         # ← 你填写：用哪些视频
├── videos/                 # ← 你放入：所有视频文件（mp4/avi/mov 等）
│   ├── video_1.mp4
│   ├── video_2.mp4
│   └── ...
│
├── tasks.json              # 中间产物：步骤①输出的任务清单
├── results.json / results.csv   # 中间产物：步骤②输出的生成结果
└── final.json / final.csv       # 最终产物：步骤③输出的校验后数据集
```

## 快速上手（5 分钟）

### 第一步：准备输入文件

> 项目已经提供了 CSV 模板文件，你可以直接用 Excel 打开后另存为 `.xlsx`。

**① 类目配置**

用 Excel 打开项目中的 `category_config.csv`，填写你要生成数据的类目和数量，另存为 `category_config.xlsx`：

| 一级类目 | 二级类目 | 数量 |
|----------|----------|------|
| 动作识别 | 人物动作 | 30 |
| 动作识别 | 物体运动 | 20 |
| 场景理解 | 室内场景 | 25 |
| 时序推理 | 因果推理 | 15 |
| ... | ... | ... |

- **一级类目**：大类名称，如"动作识别""场景理解""时序推理""属性识别""事件理解"
- **二级类目**：小类名称，如"人物动作""室内场景""因果推理"
- **数量**：该组合要生成多少条 VQA 数据

> 脚本会自动识别列名，以下写法都支持：
> - `一级类目` / `1级类目` / `大类`
> - `二级类目` / `2级类目` / `小类`
> - `数量` / `count` / `num`

**② 视频列表**

用 Excel 打开项目中的 `video_list.csv`，在第一列填入所有视频的文件名（含扩展名），另存为 `video_list.xlsx`：

| 视频文件名 |
|-----------|
| video_1.mp4 |
| video_2.mp4 |
| video_3.mp4 |

> 视频文件名必须与实际放入 `videos/` 目录的文件名完全一致（包括扩展名和大小写）。

**③ 视频文件**

将所有视频文件复制到项目根目录下的 `videos/` 文件夹中。支持的格式：`.mp4`、`.avi`、`.mov`、`.mkv` 等 OpenCV 能打开的格式。

## 输入文件详解

### 类目配置文件（category_config.xlsx）

这是整个项目的"指挥中心"，决定了生成什么类型、什么方向的 VQA 数据。

**重要前提**：你填写的一级类目如果已经在 `prompt_templates.py` 的 `CATEGORY_GUIDES` 字典中定义过，模型会按照该类的引导语精确生成对应风格的问题。如果没定义，模型会使用默认引导语（"问题需要观看视频才能回答"），关键词校验也会自动跳过。建议在填写前先看一下下文[扩展类目体系](#扩展类目体系)章节，了解已有哪些类目。

**格式示例**：

| 一级类目 | 二级类目 | 数量 |
|----------|----------|------|
| 动作识别 | 人物动作 | 30 |
| 动作识别 | 物体运动 | 20 |
| 场景理解 | 室内场景 | 25 |
| 场景理解 | 室外场景 | 20 |
| 时序推理 | 因果推理 | 15 |
| 属性识别 | 颜色识别 | 10 |
| 属性识别 | 数量统计 | 10 |
| 事件理解 | 事件描述 | 20 |

上述配置会生成 30+20+25+20+15+10+10+20 = **150 条 VQA 任务**。

**注意事项**：
- 数量必须是正整数
- 一样的"一级类目+二级类目"可以写多行，会被当作独立条目处理
- 空行会被自动忽略

---

### 视频列表文件（video_list.xlsx）

列出所有参与评测的视频文件。**文件名必须与 `videos/` 目录下的实际文件名完全一致**。

**格式示例**：

| 视频文件名 |
|-----------|
| office_walk_01.mp4 |
| street_scene_sunny.mp4 |
| kitchen_cooking_01.mp4 |
| basketball_match_highlight.mp4 |
| traffic_intersection_night.mp4 |

**任务分配规则**：
- 如果任务数（150 条）> 视频数（50 个），视频会循环使用，即每个视频被分配到约 3 条任务
- 如果视频数 > 任务数，多余的视频不会被使用
- 类目和视频的匹配是**随机打乱的**，确保数据多样性

---

### 视频文件目录（videos/）

就是普通的文件夹，把视频放进去即可。

**支持的视频**：OpenCV 能打开的主流格式都行（mp4、avi、mov、mkv、webm 等）。

**建议**：
- 单个视频时长建议 10 秒 ~ 5 分钟，太长的视频抽帧信息密度会降低
- 视频内容与你填写的类目要相关——如果你的类目是"厨房烹饪"，视频就别全是街景
- 视频文件名尽量用英文，避免中文字符导致路径问题

## 三步工作流详解

### 步骤① prepare_tasks.py —— 准备任务清单

**做什么**：读取类目配置 + 视频列表 → 按数量展开任务 → 随机分配难度和视频 → 输出 `tasks.json`

**不调用任何模型**，纯本地计算，秒级完成。

**难度分配规则**（默认比例，可在脚本顶部 `DIFFICULTY_WEIGHTS` 修改）：

| 难度 | 比例 | 说明 |
|------|------|------|
| 简单 | 30% | 直接可见的信息，不需要推理 |
| 中等 | 40% | 需要观察多个片段并结合上下文 |
| 困难 | 30% | 需要时序推理、因果分析或细节识别 |

**输出：tasks.json**

```json
[
  {
    "data_id": "VQA_00001",
    "一级类目": "动作识别",
    "二级类目": "人物动作",
    "视频文件名": "video_1.mp4",
    "目标难度": "中等"
  },
  ...
]
```

**运行命令**：
```bash
python prepare_tasks.py
```

**常见报错**：
- `类目配置文件不存在` → 检查是否创建了 `category_config.xlsx`
- `视频列表文件不存在` → 检查是否创建了 `video_list.xlsx`
- `列名识别失败` → 检查 Excel 是否包含"一级类目""二级类目""数量"三列

---

### 步骤② generate_vqa.py —— 批量生成 VQA 数据

**做什么**：逐条读取 `tasks.json` 中的任务 → 对每个视频调用 Qwen VL 模型 → 模型"观看"视频后生成问题+答案 → 输出 `results.json` 和 `results.csv`

**核心流程**（对每条任务）：

```
1. 读取任务（类目 + 视频 + 目标难度）
     ↓
2. 打开视频文件，均匀抽取最多 64 帧画面
     ↓
3. 将帧序列 + 生成指令发给 Qwen VL 模型
     ↓
4. 模型返回 JSON：{ prompt, 参考答案, 难度 }
     ↓
5. 解析 JSON，检查字段完整性
     ↓
6. 失败则自动重试（最多 2 次），仍失败则标记"需复核"
     ↓
7. 保存到 results.json / results.csv
```

**使用的模型**：`qwen3.6-plus`（可在脚本顶部 `MODEL` 变量修改为其他 VL 模型）

**每条任务的耗时**：取决于视频时长和模型响应速度，通常 5~30 秒/条。

**断点续跑**：如果中途中断（网络断开、程序崩溃等），重新运行 `python generate_vqa.py` 即可自动跳过已完成的条目，从断点继续。详见[断点续跑](#断点续跑)章节。

**进度保存**：每处理 5 条自动保存一次，不会因意外中断丢失全部进度。

**运行命令**：
```bash
python generate_vqa.py
```

**常见报错**：
- `任务文件不存在` → 先运行步骤① `python prepare_tasks.py`
- `视频文件不存在` → 检查 `video_list.xlsx` 中的文件名与 `videos/` 目录实际文件是否一致
- `API 调用失败` → 检查 API Key 是否有效、网络是否正常、账户是否有余额

---

### 步骤③ validate.py —— 校验生成结果

**做什么**：读取 `results.json` → 对每条记录执行自动校验 → 输出 `final.json` 和 `final.csv`

**校验项目**：

| 校验项 | 说明 | 严重程度 |
|--------|------|----------|
| prompt 为空 | 模型生成失败，问题文本缺失 | 严重 → 需重生成 |
| 参考答案为空 | 模型生成失败，答案缺失 | 严重 → 需重生成 |
| 难度值异常 | 难度不是"简单/中等/困难"之一 | 轻微 |
| 类目相关性 | prompt 中的关键词是否与目标类目匹配 | 需复核 |
| prompt 质量 | 是否过短、过于简单、包含主观判断词 | 需复核 |

**校验结论**：

| 结论 | 含义 | 建议处理 |
|------|------|----------|
| 通过 | 全部校验通过 | 直接使用 |
| 需复核 | 存在可能需要人工判断的问题 | 打开 CSV 查看"问题详情"列，人工判断是否可用 |
| 需重生成 | 存在严重缺陷 | 可删除 results.json 中对应条目，重跑步骤② |

**运行命令**：
```bash
python validate.py
```

**常见报错**：
- `结果文件不存在` → 先运行步骤② `python generate_vqa.py`

## 断点续跑

`generate_vqa.py` 支持断点续跑，适用于以下场景：
- 网络不稳定，中途断开
- 电脑需要关机/休眠
- 任务量大，需要分多次跑完

**工作原理**：

1. 每次运行时，先检查 `results.json` 中已有的记录
2. 状态为"正常"的条目自动跳过，不重复调用模型（省时省钱）
3. 状态为"需复核"的条目会重新生成
4. 进度每 5 条自动保存

**手动清理重跑**：如果你想重跑某些失败的条目：

```bash
# 方法：直接删除 results.json 中对应的条目，然后重跑步骤②
# 或者在 Excel 中打开 results.csv，筛选出需要重跑的条目，手动删除后再跑
```

**完全重跑**（慎用）：

```bash
rm results.json results.csv   # 删除结果文件，从头开始
python generate_vqa.py
```

## 扩展类目体系

项目内置了 5 个一级类目的引导语（定义在 `prompt_templates.py` 中）。如果你的类目不在其中，虽然可以正常生成数据，但关键词校验会跳过，生成质量可能不如内置类目精准。

### 已内置的类目

| 一级类目 | 类目焦点 | 关键词数量 |
|----------|----------|------------|
| 动作识别 | 视频中人或物体的动作/运动 | 20 |
| 场景理解 | 场景环境、物体关系、空间布局 | 20 |
| 时序推理 | 事件先后顺序、因果关系、时间逻辑 | 20 |
| 属性识别 | 物体属性（颜色、大小、形状、数量等） | 18 |
| 事件理解 | 事件含义、目的、结果、人物互动 | 18 |

### 如何添加新类目

1. 用文本编辑器（记事本/VSCode 等）打开 `prompt_templates.py`

2. 找到 `CATEGORY_GUIDES` 字典（约第 17 行），在里面添加你的新类目：

```python
CATEGORY_GUIDES = {
    # ... 已有类目不要动 ...

    # 新增：情感识别类目
    "情感识别": {
        "引导语": (
            "问题必须聚焦视频中人物的情绪和情感状态。"
            "例如：'他看起来是什么心情''她的表情表达了什么情绪''为什么他会有这样的反应'。"
            "问题需要观察人物面部表情、肢体语言和语音语调才能回答。"
        ),
        "关键词": [
            "情绪", "情感", "表情", "心情", "高兴", "难过", "生气", "惊讶",
            "反应", "感受", "态度", "开心", "悲伤", "愤怒", "紧张"
        ],
        "反例": "❌ 不要问单纯的动作或物体属性问题"
    },
}
```

3. 保存文件，然后在 `category_config.xlsx` 中就可以使用"情感识别"作为一级类目了。

**三个字段的含义**：

| 字段 | 作用 | 对模型的影响 | 对校验的影响 |
|------|------|-------------|-------------|
| 引导语 | 告诉模型生成什么风格的问题 | 直接注入到发给模型的 Prompt 中 | 无 |
| 关键词 | 校验时用来判断 prompt 是否和类目匹配 | 无 | 校验时检查 prompt 是否包含至少 1 个关键词 |
| 反例 | 告诉模型不要生成什么类型的问题 | 直接注入到发给模型的 Prompt 中 | 无 |

**引导语编写技巧**：
- 用中文写，越具体越好
- 给出问题类型的示例："例如：'xxx''xxx'"
- 强调"需要观看视频才能回答"这个核心要求
- 反例要明确，帮助模型规避常见错误

## 配置参数一览

### prepare_tasks.py 配置项

| 参数 | 位置 | 默认值 | 说明 |
|------|------|--------|------|

## 常见问题（FAQ）

### Q1：我没有阿里云百炼的 API Key 怎么办？

A：前往 [阿里云百炼控制台](https://bailian.console.aliyun.com/) 注册账号并开通 DashScope 服务，在 API Key 管理页面创建密钥。新用户通常有免费额度。

### Q2：生成一条数据大概要多久？

A：取决于视频长度和模型响应速度，通常 5~30 秒/条。100 条任务大概需要 10~50 分钟。

### Q3：生成一条数据要多少钱？

A：DashScope 按 token 计费，Qwen VL 模型视频理解的价格约为 0.001~0.01 元/条（视视频长度和帧数而定），具体以阿里云官方定价为准。

### Q4：视频太大/太多会不会很慢？

A：脚本默认每个视频最多抽取 64 帧，所以视频时长对速度影响不大。如果视频很多（上百个），总时间线性增长。

### Q5：提示"视频文件不存在"怎么办？

A：检查 `video_list.xlsx` 中的文件名是否与 `videos/` 目录下的实际文件名**完全一致**（包括扩展名、大小写、有没有多余空格）。

### Q6：生成的问题质量不高怎么办？

A：几个可能的优化方向：
1. 在 `prompt_templates.py` 中优化对应类目的"引导语"和"反例"
2. 提高 MAX_FRAMES（如改为 128），抽取更多帧
3. 在 `generate_vqa.py` 中尝试更强的模型（如 `qwen-max`）
4. 检查视频内容是否与类目匹配——如果类目是"厨房烹饪"但视频是足球比赛，模型也很难生成好问题

### Q7：可以只重跑部分条目吗？

A：可以。打开 `results.json`，删除需要重跑的条目（整条 JSON 对象），保持文件格式完整，然后重新运行步骤②即可。

### Q8：最终 CSV 用 Excel 打开中文乱码怎么办？

A：项目输出 CSV 使用 UTF-8 BOM 编码（`utf-8-sig`），Excel 应该能正常打开。如果仍然乱码，用 Excel 的"数据 → 从文本/CSV 导入"功能，选择 UTF-8 编码导入。

### Q9：同一个视频可以生成多条不同的问题吗？

A：可以，而且这正是设计意图。当任务数超过视频数时，视频会循环分配。同一个视频搭配不同的类目和难度，会生成完全不同的问题。

### Q10：支持哪些视频格式？

A：所有 OpenCV 支持的格式：mp4、avi、mov、mkv、webm、flv、wmv 等。推荐使用 mp4，兼容性最好。

### Q11：程序中途报错退出了怎么办？

A：直接重新运行步骤②即可，断点续跑机制会自动跳过已完成的条目。丢失的只是最后不到 5 条的进度。

### Q12：我可以把 final.csv 直接拿去用吗？

A：建议筛选"校验结果"列为"通过"的条目直接使用。"需复核"的条目建议人工看一下"问题详情"列，判断是否可用。"需重生成"的条目不建议使用，需要重跑。
